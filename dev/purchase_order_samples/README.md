# 발주서 데모 샘플 v2 — 작성·추출 경로가 다른 세 문서

모든 회사·상호·담당자·연락처·문서번호·주문은 체험용 가상 데이터다. 연락처는 example.invalid만 사용한다. 실제 전화번호·주소·사업자번호는 없다. XLSX의 셀과 문서 메타데이터, CSV, JSON에 가상 데이터임을 표시했다.

이 문서는 샘플 v2의 구조·기대 결과를 설명한다. 이후 새 양식에 맞춘 실제 파싱·검수·화면·다운로드는 [체험 데모 문서](../purchase_order_demo/README.md)에 구현 및 검증 절차를 정리했다. 샘플 데이터와 expected는 데모 구현과 분리해 유지한다.

## 공개 샘플

경로: frontend/public/samples/purchase-orders/

| 파일 | 실제 작성·추출 경로 | 구조 |
| --- | --- | --- |
| purchase_order_A.xlsx | 소형 거래처가 엑셀로 작성 후 인쇄 | 인쇄발주서 시트. 가상 NU 로고/상호, 문서번호, 담당자, 납기, 병합 셀, 10품목, 기재 합계와 요청사항. A4 세로 1페이지 맞춤 및 인쇄 영역 지정 |
| purchase_order_B.xlsx | 가상 쇼핑몰 관리자의 원시 주문 내역 내보내기 | orders_export 시트의 17열·18주문. 첫 행 헤더, 장식·병합·계산 수식 없음. 주문상태·판매상품번호·옵션·시각·납기 포함. export_info 시트에 내보내기 정보 |
| purchase_order_C.xlsx | 제조업체 구매 부서의 발주서 | 구매발주서 시트. 구매품번, 품목명과 규격 분리, 단위·소수 수량·단가·품목별 납기·비고. 중간 구분행·빈 행·소계·총계 포함 |

item_master.csv는 공통 16품목 마스터다. 필수 5열과 가상 데이터 고지 열을 유지했다. 별칭은 |로 구분한다. 위생장갑은 M/L에 공통으로 남기고 위생장갑 M/L 및 다목적세정제 원액 같은 명시적 조합 별칭을 추가했다.

common_delivery_statement_template.xlsx는 기존 공통 출력 템플릿과 원본추적 시트를 유지한다. 실제 사용자의 자료나 개인정보는 포함하지 않는다.

## B: 취소 제외 → 품목 매칭 → 취합

1. 주문상태가 취소/취소완료인 원본 5·11·17행을 매칭 전에 제외한다. 취소 행 중 미등록 품목과 모호한 별칭이 있어도 검수 대상으로 세지 않는다.
2. 판매상품번호 SHOP-*는 마스터의 S*** 품목코드가 아니다.
3. 상품명+옵션이 유일한 별칭이면 확정한다. 위생장갑 + M은 S003이지만 옵션이 없는 위생장갑은 S003/S004 확인 필요다. 단가로 결정하지 않는다.
4. 정상 주문을 품목코드+단위+단가로 취합한다. 서로 다른 가격의 주문은 같은 그룹으로 합치지 않는다.
5. 취합 결과의 sources에 모든 원본 파일·시트·행·셀을 남긴다. 각 입력 행의 output_group으로 역방향 추적도 가능하다.

정상 원본 13행을 6품목으로 취합한다. 예: 물티슈는 원본 2·4·8행의 수량 3+5+4=12팩, 공급가액 21,600원이다. 취소된 17행의 10팩은 포함하지 않는다.

## C: 주문행과 레이아웃 행 구분

헤더는 10행이다. 실제 주문행은 12·13·15·16·17·19·20·21·23·24·25행의 11개다.

- 구분행: 11·18행
- 빈 행: 14·22·27행
- 소계·총계: 26·28행

expected의 layout_rows에 비주문행 종류와 위치를 따로 기록한다. 소계·총계를 다시 품목에 포함해 이중 합산하지 않는다. 다목적세정제는 수량 2.75L를 포함한다. 니트릴장갑은 품목명과 규격 M/L을 합쳐 마스터와 매칭한다.

## 파일마다 다른 검수 사례

| 샘플 | 원본 시트 | 원본 행 | 의도한 판정 |
| --- | --- | --- | --- |
| A | 인쇄발주서 | 15 | 필수 수량 누락 / 역산 금지 |
| A | 인쇄발주서 | 19 | 3×4,500=13,500원, 기재 13,000원 불일치 |
| B | orders_export | 9 | 위생장갑 옵션 미선택 / M·L 확인 필요 |
| B | orders_export | 13 | 미등록 가상 정전기제거패드 |
| C | 구매발주서 | 15 | 미등록 가상 내열필터 HT-01 |
| C | 구매발주서 | 21 | 필수 수량 누락 / 역산 금지 |
| C | 구매발주서 | 24 | 6×1,800=10,800원, 기재 10,000원 불일치 |

같은 네 오류를 모든 파일에 복제하지 않았다. 확인 필요 행은 자동 확정·보정하지 않고 부분 합계에서 제외한다. B 취소 3행은 검수 오류 7행과 별개다.

## 새 예상 결과와 금액 정책

| 샘플 | 주문 원본 | 정상 원본 | 검수 | 취소 제외 | 확정 출력 품목 | 공급가액 | VAT | VAT 포함 부분 합계 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A | 10 | 8 | 2 | 0 | 8 | 122,400 | 12,240 | 134,640 |
| B | 18 | 13 | 2 | 3 | 6 | 110,500 | 11,050 | 121,550 |
| C | 11 | 8 | 3 | 0 | 8 | 126,000 | 12,600 | 138,600 |

합계: 주문 원본 39행, 정상 원본 29행, 확인 필요 7행, 취소 제외 3행, 확정 출력 22품목 행. C의 레이아웃 7행은 주문 수에 포함하지 않는다.

금액은 KRW, 세전 단가 기준이다. Decimal로 원본 행별 수량×단가를 원 단위 ROUND_HALF_UP 처리하고, 확정 출력 행별 공급가액의 10%를 같은 규칙으로 반올림해 VAT를 계산한다. B는 취합한 출력 행에 VAT를 계산한다. 현 샘플의 취합 전후 반올림 차이는 없다. 이 계산 정책은 데모에서 명시한 규칙이다.

표의 금액은 확인 필요 행과 취소 행을 제외한 부분 합계이며 최종 발행 금액이 아니다. A/C 원본 하단의 기재 합계는 검수 전 금액의 단순 합계로, 정상 변환 결과와 다를 수 있다. 원본 합계 캐시도 별도로 검산한다.

## 개발용 산출물

- structured_samples.py: 다른 세 구조·가상 데이터·의도적 오류 정의 및 expected v2 생성
- generate_samples.py, xlsx_fixture.py: 실제 XLSX/CSV/JSON 재생성
- expected/A.expected.json 등: 행별 입력·판정·출력 그룹, 취합 결과와 모든 원본 추적, C 레이아웃 행
- expected/A.errors.json 등: 의도적 오류·후보·금액 차이·원본 위치, 취소 제외 기록, generation_errors
- validate_samples.py, validate_structured.py: 생성기 데이터 정의를 참조하지 않는 독립 파일 검증 및 고정 합계 대조
- validation_report.json: 실제 검증 상태, 의도적 오류와 생성 실수 구분, 산출물 SHA-256
- test_samples.py: 취소 상태 변조·취합 추적 누락·구분행 오인·금액/수식 오염 검출 및 재생성 동일성 검사
- render_previews.py, previews/: 실제 XLSX 셀·병합·스타일에서 생성한 SVG/HTML 미리보기와 PNG

공개 샘플에는 정답 JSON을 넣지 않았다. 의도적 오류는 원본 표에서 별도 색상으로 표시하지 않는다.

## 재생성·검증

외부 패키지 없이 Python 3.12 이상으로 프로젝트 루트에서 실행한다.

```powershell
python dev/purchase_order_samples/generate_samples.py
python dev/purchase_order_samples/generate_samples.py --check
python -m unittest discover -s dev/purchase_order_samples -p "test_*.py" -v
python dev/purchase_order_samples/render_previews.py
```

재생성은 샘플과 expected만 갱신하며 API 파일은 수정하지 않는다. --check는 기존 샘플을 다시 쓰지 않고 검증 보고서만 갱신한다. ZIP/XML 순서와 시각을 고정해 반복 생성 결과가 바이트까지 같다.

## 외형 확인과 제한

previews/A.png, B.png, C.png를 로컬 Edge 헤드리스로 렌더링해 확인했다. 병합 셀·표 폭·폰트·셀 스타일을 실제 XLSX에서 읽은 미리보기다. 개발용 HTML은 앱 화면이나 변환 UI가 아니다.

Excel/LibreOffice의 네이티브 인쇄 렌더링은 수행하지 않아 인쇄 결과·정확한 페이지 수를 직접 확인한 것은 아니다. A의 A4 세로 한 페이지 맞춤·인쇄 영역 설정은 XLSX에서 검사했고, 미리보기는 Excel 출력과 다른 방식임을 명시했다. PNG는 SVG/HTML을 브라우저로 열어 캡처한 결과이며 Python 렌더 스크립트는 SVG/HTML까지 재생성한다.
