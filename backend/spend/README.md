# 구독·고정지출 찾기 데모 (backend/spend)

카드·계좌 거래내역에서 구독과 고정지출을 자동으로 찾고, 서비스명·분류를 정리한 뒤 가격 인상·무료체험 전환·중복 구독 같은
신호와 절감 후보를 보여 주는 데모. 데이터는 모두 가상이고 방문자 입력은 받지 않는다.

API: `/api/demo/spend/*` · 화면: `/demo/spend` (검색 제외, 랜딩 데모 모음에서 링크)

## 파일
```
merchants.py  가맹점명 정리(결제대행 접두어·법인 표기 제거)와 알려진 서비스 사전, 분류 목록
detect.py     반복 결제 감지 (I/O 없음): 승인취소 제거, 금액대 나누기, 주기·금액 성격·다음 결제일·신뢰도·신호
enrich_ai.py  사전에 없는 반복 결제 가맹점을 Claude 도구 호출로 정리하고 정해진 값인지 검증
service.py    분석 (I/O 없음): 서비스 정보 붙이기, 중복 표시, 합계, 결제 예정(30일), 결제 전 알림(D-3), 절감 후보,
              사람 확인 반영, 해지 상태 반영
intel.py      가맹점 사전 현황 (I/O 없음): 서비스별 표기(별칭)·출처·AI 근거·제보 건수·검수 대기, 정리율
cancel.py     해지 흐름 (I/O 없음, 가상 처리): 간편해지(사전에 있는 구독) / 해지 방법 안내(그 밖의 구독)
seed.py       가상 사용자 3명 × 2026-05-01~2026-11-15 거래내역 (일반 소비는 고정 시드)
router.py     샌드박스(메모리 2시간), AI 사용량 상한, API
```

## 감지 규칙 (detect.py 상수, 테스트로 고정)
| 항목 | 기준 |
|---|---|
| 월 주기 | 결제 간격 26~35일. 한 달 빠진 간격(54~66일)은 1번까지 허용하고 신뢰도 -15 |
| 주 주기 | 간격 6~8일 |
| 최소 횟수 | 3회. 사전·AI로 확인된 서비스는 2회. 연간 결제 서비스는 1회도 '연간 결제 추정' |
| 금액대 나누기 | 같은 가맹점이라도 한 묶음으로 주기가 안 맞으면 금액을 정렬해 40% 넘게 벌어지는 곳에서 나눈다 (통신사 회선 2개). 한 묶음으로 주기가 맞으면 나누지 않는다 (여름에 오르는 전기요금) |
| 금액 성격 | 고정 / 변동(통신·공과금·관리비, 또는 계단 모양이 아닌 변동) / 해외결제(원래 통화 금액은 같고 원화만 다름) |
| 예상 금액 | 고정: 마지막 금액, 변동: 최근 3번 중앙값, 해외결제: 최근 3번 평균 |
| 무료체험 전환 | 첫 결제 1,000원 이하 후 정상 금액 |
| 가격 인상 | 고정 금액에서 마지막이 처음(체험 제외)보다 5% 이상 높음. 해외결제는 원래 통화로 비교 |
| 해지 추정 | 다음 결제 예정일 + 유예(월 10일, 주 3일)가 기준일보다 앞섬 |
| 중복 구독 | 영상·음악·클라우드·도서콘텐츠 분류에서 진행 중인 구독이 2개 이상 |
| 신뢰도 | 횟수(2회 60 · 3회 72 · 4회 82 · 5회+ 90, 1회 50) + 사전·AI 확인 7 - 빠진 달 15. 사람이 확인하면 99 |
| 월 환산 | 주: ×52/12, 연: /12 (원 단위 버림) |

## AI 정리
- 대상: 반복 결제로 감지됐지만 사전에 없는 가맹점만. 보내는 값은 가상 가맹점명·금액·주기뿐이다.
- 응답: 도구 호출 `save_merchants`로 서비스명·분류(정해진 값)·구독/고정지출·정기 결제 여부·근거. 물어본 key 이고 정해진 값인
  것만 받는다. '정기 결제 아님'이면 목록에서 뺀다.
- 결과는 가맹점 key 기준으로 서버 메모리(`AI_CACHE`)에 보관해 다른 방문자도 재사용한다(가상 데이터라 가맹점이 같다).
- 상한: 체험 1회당 5번, 서버 전체 시간당 60번, IP당 시간당 20번. 키가 없거나 실패하면 가맹점명 그대로 '기타'로 둔다.
- 모델: `SPEND_AI_MODEL` (기본 claude-haiku-5-5)

## 가맹점 인텔리전스 (intel.py · merchants.canonical)
- 같은 서비스의 다른 표기는 한 묶음이다: 사전에 있으면 서비스명, AI가 정기 결제로 정리했으면 AI 서비스명, 둘 다 아니면 정리한 key.
  예: 9월에 결제대행이 바뀌어 `NETFLIX.COM` → `넷플릭스(NETFLIX)`로 찍혀도 넷플릭스 한 묶음 (가격 인상 감지도 이어진다).
- 사용자 확인(맞아요·구독 아님)은 그 체험의 계산에 바로 반영하고, 서버 메모리의 제보 집계(router.REPORTS)에 체험 토큰 단위로
  쌓는다(같은 체험은 1표). 제보는 사전을 바로 바꾸지 않는다. '구독 아님'이 2건 이상이고 '맞아요'보다 많으면 검수 대기로 표시.
- 정리율 = (사전 + AI) / 반복 결제 가맹점 수. 가상 데이터 기준 AI 정리 전 75%(21/28), 사전에 없는 7곳을 AI가 정리하면 100%.

## 결제 전 알림·해지 (service._alerts · cancel.py)
- 결제 전 알림: 기준일 다음 날부터 3일 안에 나갈 반복 결제(D-1~D-3).
- 해지는 실제 서비스에 요청하지 않는 가상 처리다. 고정지출은 해지 대상이 아니다.
  - 간편해지: 사전에 있는 구독. 요청 → 처리 중 → 4초 뒤 완료 (화면이 처리 중이면 다시 불러온다)
  - 해지 방법 안내: 그 밖의 구독. 일반적인 순서(서비스마다 메뉴 이름이 달라 구체 경로는 쓰지 않음)를 보여 주고 '해지했어요'로 완료
  - 완료된 구독은 합계·중복·결제 예정·절감 후보에서 빠지고 summary.saved_monthly 에 더한다. '되돌리기'로 원래대로.

## API
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /sandbox | 체험 시작 (토큰, 가상 사용자, 기준일) |
| GET | /personas/{id}/analysis | 분석 결과 (합계·구독·알림·결제 예정·절감 후보·거래내역) |
| POST | /personas/{id}/enrich | 사전에 없는 가맹점 AI 정리 |
| POST | /personas/{id}/series/{sid}/review | 맞아요(confirm)·구독 아님(reject)·되돌리기(reset) |
| POST | /personas/{id}/series/{sid}/cancel | 해지 요청(request)·해지했어요(confirm)·되돌리기(undo) |
| GET | /merchants | 가맹점 사전 현황 |
헤더 `X-Spend-Sandbox` 필요.

## 절감 후보 (최소 금액 기준)
- 중복: 가장 비싼 하나만 남길 때 나머지 합계
- 최근 90일 안에 체험에서 유료로 바뀐 구독: 월 요금
- 가격 인상: 인상분
