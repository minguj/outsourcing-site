# 운영 플랫폼(PMS) 데모

API: `/api/demo/pms/*` · 화면: 2단계에서 `/demo/pms` (검색 제외, 공개 화면 미링크 예정)

시니어하우징·임대주택처럼 **소유주가 다른 여러 사업장을 위탁 운영**하는 상황을 가정한 운영 플랫폼 샘플.
공개된 채용 공고의 범위(고객·사업장·호실·계약·청구·수납, Multi-site, 역할별 권한, 개인정보 보호)를 바탕으로
첫 버전(MVP)을 어떻게 설계할지 보여 주는 개인 샘플이다. 운영사·소유주·사업장·사람은 모두 가상이다.

## 구조
```
backend/pms/
  billing.py   청구·수납 계산 (I/O 없음): 일할 계산, 서비스 이용료, 납부 기한, 연체료, 청구서 상태
  access.py    역할 × 사업장 권한 (I/O 없음): 역할별 권한, 사업장 범위, 연락처 가림, 건강정보 열람 제한
  service.py   업무 규칙: 호실 현황, 입주자 조회(감사 기록), 서비스 이용 기록, 계약 상태 흐름, 월 청구 실행, 수납
  seed.py      가상 샘플 데이터 (사업장 2곳, 호실 20개, 입주자 7명, 체험 사용자 6명)
  router.py    API (입출력 변환, 샌드박스)
backend/tests/test_pms_demo.py
```

## 데이터 모델
```
운영사 ─ 소유주 ─ 사업장(자산 유형, 요금표, 납부일·연체 이율) ─ 동·층 ─ 호실(정비 여부)
입주자 ─ 보호자 / 건강·돌봄 정보(별도 열람 권한)
계약: 호실·입주자·기간·보증금·월 이용료·상태
청구서: 계약 × 월 (한 번만 생성), 청구 항목(월 이용료 + 서비스 이용료)
수납: 청구서별 부분 납부
서비스 이용: 입주자·서비스·수량·날짜 (사업장 요금표에 있는 서비스만)
감사 기록: 누가 언제 어떤 입주자의 민감 항목을 원문으로 봤는지
```
운영 데이터에는 모두 `site_id`가 있고, 모든 조회는 서버에서 사용자 범위로 거른다.
공통 구조는 같고 사업장별로 요금표·납부일·연체 이율만 다르게 둬서, 자산 유형이 달라도 같은 코드로 동작한다.

## 역할과 권한
| 역할 | 사업장 범위 | 주요 권한 |
|---|---|---|
| 본사 관리자 | 전체 | 사업장·계약·청구 조회, 연락처 열람, 감사 기록 (청구 실행·건강정보는 불가) |
| 사업장 매니저 | 배정 사업장 | 계약 상태 변경, 월 청구 실행, 수납, 연락처·건강정보 열람, 감사 기록 |
| 현장 케어 직원 | 배정 사업장 | 건강·돌봄 정보 열람, 서비스 이용 기록 (연락처는 가림, 계약·청구 불가) |
| 회계 담당 | 배정 사업장 | 계약 조회, 월 청구 실행, 수납, 연락처 열람 (건강정보 불가) |
| 보호자 | 본인 가족 | 가족의 청구서·기본 정보 조회만 |

- 범위 밖 데이터는 403이 아니라 404로 응답해 존재 여부도 드러내지 않는다.
- 연락처·건강정보를 원문으로 보여 주면 감사 기록에 남긴다.

## 계약 상태
`작성 중 → 체결 → 입주 → 해지`, `작성 중/체결 → 취소`
- 정비 중인 호실, 같은 호실에 진행 중인 다른 계약이 있으면 체결·입주할 수 없다.
- 해지 시 퇴거일을 기록한다. 퇴거일 전까지는 호실이 '입주'로 보인다.

## 청구 규칙 (사업장 요금표로 바꿀 수 있는 가정)
- 월 이용료는 그 달에 계약이 유효한 날수만큼 일할 계산 (입주일·퇴거일 포함), 10원 미만 버림.
- 서비스 이용료 = 그 달 이용 수량 × 사업장 단가.
- 납부 기한 = 다음 달 사업장 납부일 (말일보다 크면 말일).
- 연체료 = 남은 원금 × 연 이율 × 연체 일수 / 365 (단리, 10원 미만 버림).
- 같은 계약·같은 달 청구는 다시 실행해도 한 번만 만든다.
- 테스트 기대값은 손으로 계산했다 (엔진 출력을 복사하지 않는다).

## 샌드박스
- `POST /sandbox`로 방문자마다 가상 데이터 사본을 메모리에 만든다. 2시간 뒤 지우고 DB에 남기지 않는다(최대 300개, IP당 시간당 30개).
- 이후 요청은 `X-Pms-Sandbox`(토큰)와 `X-Pms-User`(체험 사용자 id) 헤더로 보낸다. 사용자 id를 바꾸면 역할이 바뀐다.
- 실제 개인정보를 받거나 저장하지 않는다.
